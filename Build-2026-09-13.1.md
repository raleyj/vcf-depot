# VCF Offline Depot 1.1.0

Final distribution build **2026-09-13.1** for **VCF 9.1 and newer**. Workflow testing is demonstrated on **VCF 9.1.1**; verify compatibility before adopting later VCF releases.

This build supersedes the September 7 distribution while retaining appliance version 1.1.0.

## Changes

- Initial and subsequent release retrieval controls for the VCF Installer on Authorize & Download.
- Automatic separate request for catalog-selected bootable ESX installer media, with integrity validation.
- Recoverable network changes and durable audit handling.
- Asynchronous cached diagnostics, support bundle concurrency control, and explicit degraded or unknown health states.
- A restricted depot-web management service and a root-owned allowlisted helper. The web service cannot access the Docker socket or replace privileged code.
- Root-side signature validation and application rollback for signed updates.
- Consistent navigation and maintenance controls, plus updated operating guides.
- Fresh-deployment ownership initialization for administrator state and the public HTTPS certificate.

## Validation and scope

The exact OVA passed isolated fresh DHCP deployment, first-boot administrator initialization, HTTPS login, automatic depot startup, restricted service identity, authenticated content range retrieval, payload hash verification, and reboot persistence. OVF networking and credential-validation tests also passed.

The final live runtime successfully refreshed Broadcom metadata after re-registration. All binary payloads already existed, so no fresh Broadcom binary transfer was required in that acceptance test. Earlier Installer retrieval succeeded; the complete Installer retrieval workflow was not repeated during this release run. The fresh OVA does not contain Broadcom software, authorization, credentials, or downloaded binaries.

VCF Installer is the supported integration target. Deployment still requires an entitled Broadcom account, the supported Linux VCF Download Tool, network access, and certificates appropriate for your environment. This is a community appliance; successful lab qualification is not a vendor support certification.

## Deployment and verification

Deploy as a fresh appliance with 4 vCPUs, 8 GiB memory, a 32 GiB OS disk and a new 1 TiB depot data disk. DHCP and Etc/UTC are the defaults. Supply distinct administrator, maintenance, and console recovery credentials in the OVF deployment properties. Existing configuration and binaries are not migrated by importing this OVA.

Verify SHA256SUMS and its signature with the supplied release public key after establishing trust in that key independently. See the Deployment Guide and release-record.json for details.
